\begin{abstract}
\texttt{rewrite} is a small interpreted language for symbolic and numerical
mathematics, written in the early 1990s and revived in 2026. Unlike most
computer algebra systems, its kernel contains no mathematics: data types,
operators, the laws of algebra, differentiation and integration rules are
all defined in plain-text include files and applied by term rewriting. Rule
sets (``algebras'') are first-class objects that can be combined into
sequences and fixpoint iterations. A \texttt{LIFT} statement transfers all
rules of one set of operations to another, so that, for example, the rules
of an abelian group written for $+$ also apply to $\cdot$ in a field.
Numerical evaluation is interleaved with rewriting: as soon as all
arguments of a function are numbers, an attached C function computes the
value. We describe the design of the language, its revival on current
64-bit compilers, and its extension by static subsorts, which add exact
integers and fractions as sorts below the real numbers without changing
any rule of the library, and sorts of non-negative and positive numbers
for which rules like $\sqrt{x^2}=x$ hold. As a case study, the rule-based
integrator Rubi was translated into \texttt{rewrite}. A translator converts
97\% of Rubi's rules automatically; for this, the language gained ordered rule lists
with a backtracking matcher for optional pattern parts, commutative
operators and condition lists, symbolic helper functions and special
functions. On \nproblems{} integration problems from four independent
textbook collections, \psolved{} of the results are verified correct by
numerical differentiation. On top of the integrator, limits, definite
integrals and the Laplace and Fourier transforms are further rule files,
with which ordinary and partial differential equations are solved.
\end{abstract}

\section{Introduction}

Computer algebra systems such as Mathematica~\cite{mathematica} or
SymPy~\cite{meurer2017sympy} come with a large body of built-in mathematical
knowledge. A user can add rules, but the core simplification and the
calculus routines are part of the system and are mostly hidden from the
user. Term rewriting systems such as Maude~\cite{clavel2007maude} take the
opposite view: they provide a general rewriting engine and leave the
mathematics to the user, but they are usually not aimed at numerical work.

\texttt{rewrite} sits between these positions. Its interpreter knows how to
parse expressions with user-defined operators, how to match and replace
terms, and how to call C functions for numerical values. Everything else is
defined in include files: the sort \texttt{real}, the operators \texttt{+},
\texttt{*} and \texttt{\^}, the group, ring and field laws, the
differentiation rules, and numerical algorithms such as Simpson integration.
The language was designed by the author between 1992 and 1996 on Unix and
the Amiga, on top of a scanner and parser framework by Axel T.\ Schreiner
and inspired by the lectures on term replacement systems by Volker Sperschneider.
In 2026 it was ported to current compilers and extended with a test suite,
exact numbers and a rule-based integration library.

The main contributions of this paper are:
\begin{itemize}
  \item a description of a language in which mathematics is a library of
        rewrite rules, including the \texttt{LIFT} mechanism for transferring
        rules between algebraic structures;
  \item the interleaving of symbolic rewriting and numerical evaluation,
        which allows numerical algorithms to be written as rewrite rules;
  \item static subsorts with value conversion, which add exact integers and
        fractions to the language as a library, with the rules of the real
        numbers inherited through \texttt{LIFT};
  \item an automatic translation of the rule-based integrator
        Rubi~\cite{rich2018rubi} into \texttt{rewrite}, with a measurement on
        independent test problems and a discussion of what the translation
        requires from the host system;
  \item limits, definite integrals and integral transforms written as rule
        files on top of the integrator, applied to ordinary and partial
        differential equations.
\end{itemize}

\section{Language design}

\subsection{Sorts, operators and numbers}

A program first declares sorts (types) and operators. The following
complete program defines real numbers with three operators and evaluates
expressions:

\begin{lstlisting}
SORT real                                 # a data type
REALNUM real                              # numbers typed in have sort real
FUNC + : real,real >> real LA2 ATT plus   # left-associative, priority 2
FUNC * : real,real >> real LA3 ATT mult    # binds tighter than +
FUNC ^ : real,real >> real RA  ATT power   # right-associative
1+2*3                                     # prints 7
2^3^2                                     # prints 512
SYM x,y : real
x+y*2                                     # prints x + y * 2
\end{lstlisting}

The format words \texttt{LA1}--\texttt{LA5}, \texttt{RA} and \texttt{RU}
define left-associative binary operators of five priorities,
right-associative operators and right unary operators such as the
factorial. \texttt{ATT name} attaches a C function from a table of user
functions. It is called whenever all arguments of the function are numbers;
otherwise the term stays symbolic. \texttt{OTHER} adds further meanings to
an existing name for other argument sorts, so that \texttt{+} can mean
addition of reals, complex numbers or vectors. \texttt{BRA} defines
functions written with brackets, such as a scalar product
$\langle a,b\rangle$.

Each sort has its own representation in C. Real numbers are
\texttt{double} values; the standard library defines complex numbers, real
vectors and matrices, whose values are C arrays. Operations on whole
vectors and matrices are executed by C functions, so they run at compiled
speed.

\subsection{Rules and algebras}
\label{sec:rules}

Rules are collected in named rule sets, called \emph{algebras}. A rule has
a left side, a right side, an optional condition and an optional block of
instructions that is executed before the replacement:

\begin{lstlisting}
PAT A : real
ALG simp
SPEC    simp : A*1 = A             # SPEC starts a new rule set
ADDSPEC simp : A+0 = A             # ADDSPEC adds a rule
SYM u : real
REWR (u*1)+0 : simp                # prints u
\end{lstlisting}

\texttt{PAT} declares pattern variables that match any term of their sort.
\texttt{NUMPAT} declares pattern variables that only match numbers, which makes
rules like ``evaluate if the argument is a number'' easy to write. Pattern
variables are ordinary names, so a user who assigns a term to a name used
by a library rule changes that rule; the pattern variables of the library
therefore all begin with an underscore (\texttt{\_X}, \texttt{\_N}), and
names like \texttt{X} are left to the user.
Conditions test whether a term occurs in another one (\texttt{IN},
\texttt{NIN}), compare terms in a total order (\texttt{LB}, used for
sorting sums), or evaluate any expression with a boolean result.

Algebras are combined into lists. A list in parentheses is applied
repeatedly until no rule changes the term any more. The standard rule list
of the library is defined like this:

\begin{lstlisting}
SPEC All : Std,Doit,(Linear,Compl,diff,GrRi),AGroup,integr,
           (Subst,GrRi),Std,Combine,NoMi,Final,Expprod,Final
\end{lstlisting}

\texttt{Final} brings the result into a normal form, which puts equal
factors next to each other, so that \texttt{Expprod} can combine
$e^a e^b$ to $e^{a+b}$. With the library loaded,
\texttt{REWR D(sin cos x,x) : All} returns
\texttt{- cos (cos (x ))* sin (x )}.

\subsection{Transferring rules with LIFT}

A distinctive feature of \texttt{rewrite} is the \texttt{LIFT} statement.
It declares that all rules valid for one set of functions and constants
also hold for another set. The standard library writes the laws of a group
once and transfers them step by step:

\begin{lstlisting}
LIFT (_Ag+_Ag,_Ag-_Ag,-_Ag,0g) TO (_Aag+_Aag,_Aag-_Aag,-_Aag,0ag)
LIFT (_Aag+_Aag,_Aag-_Aag,-_Aag,0ag) TO (_Ar+_Ar,_Ar-_Ar,-_Ar,0r)
LIFT (_Aag+_Aag,_Aag-_Aag,-_Aag,0ag) TO (_Ar*_Ar,_Ar/_Ar,mi(_Ar),1r)
\end{lstlisting}

The last line reuses the rules of an abelian group for multiplication,
division, the multiplicative inverse \texttt{mi} and the neutral element 1
of a ring. In the same way, linearity is written once for a generic linear
function and lifted to differentiation, integration, Taylor expansion and
summation. Each symbol can be lifted from one other symbol, so the lifted
operators form a tree, and a rule applies to a term whose operator reaches
the operator of the rule along this tree. This corresponds closely to the
algebraic hierarchies of modern proof assistants~\cite{mathlib2020}, but
here it acts directly on the rewrite rules.

\subsection{Exact numbers as subsorts}

Exact arithmetic was added in 2026 without changing the rules of the
library, by two sorts and two new statements. The sorts \texttt{integer}
(arbitrary size) and \texttt{rational} (fractions) are implemented in C with
the GMP library~\cite{gmp} and declared in an include file:

\begin{lstlisting}
SORT integer
SORT rational
ATT integer  show_int,cmp_int,cpy_int,del_int
ATT rational show_rat,cmp_rat,cpy_rat,del_rat
SUBSORT integer,rational ATT int2rat     # every integer is a fraction
SUBSORT rational,real ATT rat2real       # every fraction is a real number
OTHER + : rational,rational >> rational ATT rat_plus
OTHER / : integer,integer >> rational  ATT int_div
...
LIFT (_A+_A,_A-_A,_A*_A,_A/_A,-_A,mi(_A),_A^_A)
  TO (_Aq+_Aq,_Aq-_Aq,_Aq*_Aq,_Aq/_Aq,-_Aq,mi(_Aq),_Aq^_Az)
INTNUM natural ATT read_int              # 12 is a natural number, 0.5 real
\end{lstlisting}

\texttt{SUBSORT} declares that every value of the first sort is also a value
of the second, with a C function that converts the value. Sorts remain
static: the sort of a term follows from its parts when it is built, and a
value never changes its sort at run time. A function declared for a wider
sort accepts arguments of its subsorts; if several variants of an operator
fit, the one with the fewest conversions is chosen, and the values are
converted only when the function is calculated. Thus \texttt{1/3+1/6}
uses the rational \texttt{+} and prints \texttt{(1/2)}, \texttt{2\^{}100}
is exact, and \texttt{1/3+0.5} uses the real \texttt{+} and prints
\texttt{0.833333}. A variant that fits exactly is always preferred, so that
conversions are only a fallback, as the most specific method in Julia: the
library declares \texttt{real} a subsort of \texttt{complex}, and the
hand-written variant for \texttt{real + complex} still wins over converting
the real number. Two variants that need equally many conversions (a
natural number fits both an \texttt{integer} and a \texttt{nonneg}
variant) are reported, and a more specific variant resolves the tie. The \texttt{LIFT} line lets \texttt{rational} inherit all
rules of \texttt{real}, and a second one does the same for
\texttt{integer}; \texttt{x*1+0*x+(1/2)*x} simplifies to \texttt{(3/2) * x}
with the unchanged rules for real numbers.

\paragraph{Exact constants.} With the exact sorts, a function of exact
numbers without an exact value stays a term, and $\pi$ stays a symbol, as
in Mathematica; $\ln 2$ and $\pi/6$ are not replaced by decimal numbers.
Exact values are recognized from the numerical value: rational ones
($\cos(\pi/3)=1/2$), square roots of rational ones
($\sin(\pi/3)=\sqrt3/2$) and rational multiples of $\pi$ for the inverse
trigonometric functions ($\arcsin\frac12=\pi/6$). Since a transcendental
function of a nonzero algebraic number is transcendental, such a match is
no coincidence. Conditions are still evaluated numerically.

\paragraph{Symbolic numbers.} Above \texttt{real} and \texttt{complex}
the library declares the sort \texttt{number} of symbolic scalar
expressions, like \texttt{Number} in Julia. Its operator variants have no
C function; a term is of sort \texttt{number} only when one of its parts
is. The imaginary unit \texttt{im} is a complex constant that, like
$\pi$, stays a symbol in terms; the symbolic helpers know
$\mathit{im}^2=-1$. A
pattern variable of sort \texttt{number} matches any term, and a function in
a pattern whose variant is declared on such top sorts also matches its
variants on narrower sorts, as a method for \texttt{Number} in Julia
applies to \texttt{Float64}. The right-hand side and the conditions of a
rule are evaluated with the variants for the actual sorts, so a rule
written for \texttt{number} still calculates \texttt{m > 0} for a real
\texttt{m}. The derivative and the translated Rubi rules are written this
way and apply to real integrands and to integrands with \texttt{im}
alike, while a real integrand keeps its real operators.

The sort \texttt{number} has no values of its own: it is declared above
\texttt{real} and \texttt{complex} by a \texttt{SUBSORT} without a
conversion function, and a value keeps its sort. Whether a sort can have
values at all follows from the declarations alone (a print function, a
numerical C function with this result sort, or a conversion into it), so
the interpreter needs no list of sort names. It uses this, for example, to
reject the assignment of a list to a numerical constant with a clear
message, and to convert a term of a sort without values where a value is
expected: with \texttt{SUBSORT vector,rvector ATT constr\_vec} a list of
numbers becomes a compact numerical vector when it is assigned to a
constant of that sort or passed to a numerical C function, while
\texttt{[1,2]*x} stays symbolic.

\paragraph{Non-commuting quantities.} Above \texttt{number} the library
declares the sort \texttt{algebra} of the elements of an associative
algebra, whose product need not commute, and below it the sort
\texttt{matrix}. A pattern matches the variants of a function on narrower
sorts whenever its own variant is symbolic (has no numerical C function),
so rules written for \texttt{algebra}, such as $(AB)^{-1}=B^{-1}A^{-1}$,
apply to matrices and to numbers, while the integration rules, written
for \texttt{number} with a commutative product, never see a matrix
product. Matrix equations are solved by isolating the unknown from the
left or from the right: $XA+C=B$ gives $X=(B-C)A^{-1}$.

Lists are written in brackets, which the list library declares like any
other function (\texttt{BRA [ ]}) with variants for the sorts of the
elements: a list of numbers has the sort \texttt{vector}, below
\texttt{number}, and a list of vectors the sort \texttt{matrix}, so the
choice of the variant by the argument sorts also decides whether a
product is taken element by element or as a matrix product. Thus
\texttt{[[1,2],[3,4]]*[5,6]} is the vector \texttt{[17, 39]}, explicit
matrices mix with symbolic ones, and the solutions of a system of
equations, a list of tuples, are printed as the rows of a matrix.
A transposed vector is a term of its own sort \texttt{covector}, like
Julia's \texttt{Transpose}: \texttt{transpose(u)*v} is a number (the inner
product), \texttt{u*transpose(v)} a matrix (the outer product), and
\texttt{transpose(u)*m} again a covector. For symbolic vectors the sort
alone tells the matrix rules that $u^{\mathsf T}v$ is a scalar that
commutes with matrices, and since transposition is linear, sums and
multiples of covectors are taken back to vectors, so that a handful of
declarations suffice.

\paragraph{Sorts with a known sign.} A sort may have several wider sorts,
and the conversion follows the shortest path in the resulting graph. The
library declares
\[
\mathit{natural} < \mathit{integer} < \mathit{rational} < \mathit{real},\qquad
\mathit{natural} < \mathit{nonneg} < \mathit{real},\qquad
\mathit{positive} < \mathit{nonneg},
\]
where \texttt{nonneg} and \texttt{positive} are real numbers known to be
non-negative or positive. Since the minus sign is an operator, every number
literal is \texttt{natural}, and \texttt{2-5} is the \texttt{integer} $-3$.
Operator variants such as \texttt{nonneg*nonneg >> nonneg} and
\texttt{sqrt : nonneg >> nonneg} propagate the sign through terms. Several
simplification rules are valid only for non-negative or positive
arguments: $\sqrt{t^2}=t$, $(t^a)^b=t^{ab}$, $\ln(pq)=\ln p+\ln q$. They
are now written with pattern variables of these sorts. A pattern variable whose
sort is a subsort of another only matches terms of that sort or below it,
whereas a variable of a sort without a wider sort still matches any term
as in the original language. Thus \texttt{sqrt(t\^{}2)} simplifies to \texttt{t} for
\texttt{SYM t : nonneg}, but \texttt{sqrt(x\^{}2)} stays as it is for a
real \texttt{x}.

One change in the interpreter made this work. When a rule written for
\texttt{real} rewrites a term with exact numbers, the operators of the new
term are chosen again for the sorts of their actual arguments, from the
leaves upwards and after each numerical step. The original \texttt{LIFT}
mechanism replaced all operators of one sort by those of another; that was
correct for homogeneous structures like groups and rings, but with
subsorts the arguments of one term have different sorts. Re-choosing the
variant repairs this and makes rules for \texttt{real} produce exact
results whenever their inputs are exact. The declarations are a classic
instance of order-sorted algebra~\cite{goguen1992osa}; the novelty here is
that the subsort relation, the conversions and the inheritance of rules
are all defined in the library.

Roots of exact numbers follow Mathematica. \texttt{4\^{}(1/2)} is the
integer 2, but \texttt{2\^{}(1/2)} has no exact value: the C function
for a rational power returns nothing, and the power stays a term inside
another term. Such terms are kept in a normal form: perfect powers are
taken out and exponents reduced ($\sqrt{8}=2\sqrt{2}$,
$\sqrt{4/3}=2\cdot 3^{-1/2}$, $(\sqrt{2})^2=2$), and in a simplified
product a coefficient is merged with a root of the same base
($2/\sqrt{2}=\sqrt{2}$). This needed a distinction between two kinds of
numerical evaluation that were the same before: subterms of a term are
calculated exactly or not at all, while the value of a closed expression,
for output or for a numerical test in a rule condition, falls back to real
arithmetic ($\sqrt{2}$ prints 1.41421). A real number in an operation makes
it numeric, as Mathematica's numeric contagion: $\sqrt{2}\cdot 0.5$ is
0.707107, whereas a real 1.0 next to an exact number counts as the integer
1, since the rules of the old library were written with real numbers. For
the same reason, an operation on such integers alone whose value is not an
integer is done exactly: the derivative rule
\texttt{Dt(sqrt(\_X),\_Z) = Dt(\_X,\_Z)*mi(2*sqrt(\_X))} gives $\frac12$, not
0.5, so that the derivative of $\sqrt{\pi t}$ keeps the symbol $\pi$.

\subsection{Interleaving rewriting and numerics}

After every single rewrite step, the interpreter evaluates all subterms
whose arguments are numbers. Constants that have a value are replaced by
their value when a term is copied. Together with the procedural part of
the language (\texttt{FOR}, \texttt{WHILE}, \texttt{IF}, blocks with local
constants, and user functions), this allows numerical algorithms to be
written as rewrite rules. The library defines Simpson integration as a
rule whose \texttt{DO} block computes the value:

\begin{lstlisting}
ALG calc
SPEC calc : I(_N,_K,_A,_x)=_myerg DO { _myerg=0;_tmp1=0;_tmp2=0  # Simpson
        FOR _n=_N+_step/2 TO _K-_step STEP _step DO { _x=_n;_tmp1=_tmp1+_A
        _x=_n+_step/2
        _tmp2=_tmp2+_A }
        _x=_K-_step/2
        _tmp1=_tmp1+_A
        _x=_N;_myerg=_A+4*_tmp1+2*_tmp2
        _x=_K;_myerg=(_myerg+_A)*_step/2/3
        _x=nothing }
\end{lstlisting}

A second rule set first substitutes the integration variable by the
internal variable \texttt{\_x}. With \texttt{\_step=0.01},
\texttt{REWR I(0,pi,sin(x),x) : numerik,calc} returns 2. The same
mechanism gives Newton's method and the search for minima and maxima. The
symbolic part can prepare the numerical part: \texttt{newton} expects the
derivative as an argument, which is computed symbolically by \texttt{D}.

The original application of the language was physics. The library contains
physical constants, units and formulas, and an example program computes
Bragg angles, structure factors and X-ray absorption of lithium niobate
crystals from tabulated atomic data.

\section{Case study: rule-based integration}

Differentiation is easy to express with rewrite rules, because every rule
takes the term apart and the product and chain rules always apply.
Integration is harder. Complete decision procedures exist for elementary
functions~\cite{risch1969problem,bronstein2005symbolic}, but they are not
pattern based. Rubi~\cite{rich2018rubi,rubirepo} showed that an extensive
system of carefully ordered rules with conditions can integrate a very
large class of functions. Its 199 rule files contain 7422 rules in
Mathematica syntax, published under the MIT license. We first translated a
small closed subset by hand and then wrote a translator for all of them, to
test how far the mechanisms of \texttt{rewrite} carry.

\subsection{Pattern features}

Rubi's patterns rely on features of the Mathematica pattern matcher that
the original \texttt{rewrite} did not have. A typical rule is

\begin{lstlisting}
Int[(a_. + b_.*x_)^m_, x_Symbol] := (a + b*x)^(m + 1)/(b*(m + 1)) /;
    FreeQ[{a, b, m}, x] && NeQ[m, -1]
\end{lstlisting}

where \texttt{a\_.} matches a missing summand with default 0 and
\texttt{b\_.} a missing factor with default 1. The pattern also matches
$x\,b + a$, because Mathematica matches sums and products in any order, and
the condition combines several tests. We added three corresponding
features to the language: \texttt{OPT a,b} declares pattern variables that may
be missing, \texttt{DEFAULT + = 0}, \texttt{DEFAULT * = 1} and
\texttt{DEFAULT RIGHT \^{} = 1} give the values of missing operands,
\texttt{COMM +,*} declares commutative operators, and a rule can have a list
of conditions, all of which must hold. \texttt{NIN(x,a,b,m)} tests that $x$
occurs in none of $a$, $b$, $m$, which is Rubi's \texttt{FreeQ}.

A first implementation expanded every rule into all its variants when it
was defined, so that the matcher stayed unchanged. The number of variants
grows exponentially with the number of optional parameters and commutative
products, however: the median Rubi rule would have about 1900 variants.
Rules defined while one of these features is active are therefore kept in
an ordered \emph{rule list}, as in Mathematica, and matched by a separate
backtracking matcher. Bindings of pattern variables are recorded on a trail,
so a failed alternative undoes exactly its own bindings. Swapped operands
and missing optional operands are tried in turn, and the conditions are
checked as part of the match, so a failing condition makes the matcher try
the next alternative and then the next rule. A precomputed set of possible
head symbols per rule skips most rules of a large list without running the
matcher. With these features the rule above translates almost one to one:

\begin{lstlisting}
ADDSPEC RubiRules : IF NIN(Xv,O_a,O_b), (neq(P_m,(-1)))
        Int(((O_a)+((O_b)*(Xv)))^(P_m),Xv) = ...
\end{lstlisting}

Here \texttt{P\_m} is a required and \texttt{O\_a}, \texttt{O\_b} are
optional pattern variables. One rule covers $(a+bx)^m$, $(bx+a)^m$, $(a+x)^m$,
$(bx)^m$ and $x^m$, with numeric or symbolic coefficients.

\subsection{Automatic translation}

The translator (900 lines of Python) parses Rubi's rule files with a small
Pratt parser into Mathematica's full form and writes one \texttt{rewrite}
file per Rubi file, in Rubi's loading order and with the original of every
rule as a comment. Mathematica's pattern variables become \texttt{PAT} variables, negative
numbers in patterns become \texttt{NUMPAT} variables with a condition, local
definitions (\texttt{With}, and \texttt{Module} with values only) are
substituted, helper predicates that Rubi defines inside its rule files are
inlined, and a predicate applied to a list, like \texttt{LinearQ[\{u,v\},x]},
becomes a conjunction. As in Mathematica, $e^u$ is a power whose base is a
symbolic constant $e$ of sort \texttt{positive} without a numerical value,
so that the rules for $F^u$ apply to it and $\ln e=1$ stays exact. Some
rules have a
function variable, \texttt{F\_[c\_.*(a\_.+b\_.*x\_)]} with a condition such
as \texttt{TrigQ[F]} or \texttt{MemberQ[\{Sinh,Cosh\},F]}; they are expanded
into one rule per admissible function.

\paragraph{Helper and special functions.} Rubi's conditions and right-hand
sides use about a hundred helper functions, such as \texttt{ExpandIntegrand},
\texttt{PolyQ}, \texttt{BinomialQ}, \texttt{Subst} or
\texttt{ExpandTrigReduce}. They cannot be ordinary \texttt{rewrite}
functions, which are only evaluated when all arguments are numbers. We
added symbolic C functions instead: they receive the argument terms and
return a new term, or nothing if they do not apply. About 90 of them are
implemented, from predicates on the form of a term to polynomial division,
the product-to-sum reduction of trigonometric powers, and Rubi's measures
of simplicity based on the size of a term. Their results are exact when
their inputs are.

Such functions break with the principle that the interpreter knows nothing
about the meaning of an operator: a C function that expands a product must
know which symbol is the product. To keep this dependence explicit, the
helpers are declared with \texttt{ATT SYMBOLIC} and refer to the library
only through \emph{roles} such as \texttt{"+"}, \texttt{"cos"} or
\texttt{"pi"}. By default a role is played by the symbol of the same name;
a library with other names maps them (\texttt{SYMBOLIC "cos" = "kos"}). A
head is recognized by its function family, so that the variants of an
operator for different sorts count as one. What the roles cannot express are
the algebraic properties the C code relies on, such as the commutativity of
\texttt{+}; these are documented as the contract of each role. Where a
helper only tests the form of a term, the matcher can do the work instead:
\texttt{matchq(u,~pattern,~cond)}, Rubi's \texttt{MatchQ}, runs the
backtracking matcher of the rule lists on a pattern with its own variables
and checks the condition with their bindings. It is declared with
\texttt{HOLD}, so that the pattern and the condition reach it unevaluated,
and it made 28 more rules translatable. Rubi's own form tests, such as
\texttt{LinearMatchQ} or \texttt{TrinomialMatchQ}, are defined in its
utility file with \texttt{MatchQ}; the translator now inlines these
definitions instead of using C functions for them.

Knowledge that a helper needs beyond a name, such as the derivative of the
sine, can be kept in rules as well: a function declared with
\texttt{ATT RULES alglist} is calculated by rewriting its call with the
rule list, also inside a condition and from C. The derivative used by
\texttt{DerivativeDivides} is such a function, defined with the rules for
\texttt{Dt} of the library; Rubi's \texttt{FixInertTrigFunction} is another,
translated from Rubi's definitions (44 of 60 are used: in Rubi they act on
inert functions only, which the translation does not distinguish, and 12
of them would take integrands away from the rules that solve them). A
rewriting started in the middle of a condition must set the bindings of
the rule being tried aside and restore them afterwards; with that, the
interpreter supports rule-defined functions at any depth. \texttt{ExpandIntegrand} splits rational functions into
partial fractions, as Mathematica's \texttt{Apart}: with GMP rationals, the
denominator is split into square-free parts, rational roots and the factors
given in the input, and the extended Euclidean algorithm gives the
numerators. Rubi's last general rule, $\int u\,dx=\int
\texttt{ExpandIntegrand}[u]\,dx$ if the result is a sum, then integrates
every rational function term by term. A condition like
\texttt{SumQ[ExpandIntegrand[u,x]]} needs its inner helper evaluated
first; \texttt{rewrite} calculated conditions from the outside in, so the
rule never applied until this was changed. Rubi's substitutions rest on
\texttt{FunctionOfQ} and \texttt{SubstFor}, which decide whether the
integrand is a function of, say, $\sin w$ and write it in a new variable,
also through identities such as $\cos^2w=1-\sin^2w$; with these two C
functions, 34 substitution rules for trigonometric and hyperbolic functions
became translatable. \texttt{DerivativeDivides[y,u,x]} returns $u/y'$ if it
is free of $x$, and \texttt{False} otherwise; it is a C function that stays
unevaluated when it does not apply, and \texttt{FalseQ} tests for exactly
that, so that 20 rules of the form $\int u\,f(y)\,dx=q\int f(t)\,dt$ with
$t=y$ could be translated. The substitution $x\to F^{gx}$ for functions of
exponentials is a C function that takes the place of Rubi's rule, which
uses pattern tests the translator cannot express; so are the substitution
$t=(a+bx)^{1/n}$ for fractional powers of a linear function and Euler's
substitutions for $\sqrt{a+bx+cx^2}$, whose Rubi rules pass a list of
results. A small difference had a large effect: Rubi's \texttt{GtQ[u,v]} is
false unless both are numbers, so that \texttt{Not[GtQ[a\^{}2,0]]} holds for
a symbol~$a$; translated as $u>v$, the comparison could not be calculated,
and rules such as $\int dx/\sqrt{a^2-x^2}=\arctan(x/\sqrt{a^2-x^2})$ never
applied. With a helper of Rubi's meaning, 30 more problems were solved. Many results of Rubi need special functions; 27 of them,
from the error function and the Fresnel and exponential integrals to the
incomplete Gamma function, elliptic integrals in Carlson's
form~\cite{carlson1995} and the hypergeometric function ${}_2F_1$, were
added as C functions with Mathematica's conventions, each with a derivative
rule. Their values agree with mpmath~\cite{mpmath} to within $10^{-11}$.

\paragraph{The host system's simplification.} Rubi relies on Mathematica's
automatic simplification, which \texttt{rewrite} does not have. Most of the
work after the first translation went into reproducing the parts Rubi
depends on. A normal-form rule set writes $x-y$ as $x+(-1)\,y$, $x/y$ as
$x\,y^{-1}$, $\sqrt{x}$ as $x^{1/2}$ and $(uv)^k$ as $u^kv^k$ for integer
$k$ (in the translated patterns as well), but, unlike our first version and
like Mathematica, it does not multiply out products with sums: Rubi's rules
for $(c+d\tan x)/(a+b\tan x)$ expect the product. Polynomials in the
integrand are brought into the form $c_0+c_1x+c_2x^2+\dots$ with collected
coefficients and their numeric content in front, and every rule result is
simplified trivially ($u^0$, $u^1$, $1\cdot u$, $0+u$). In Mathematica,
some rules that make no progress are harmless because exact arithmetic or
other rules prevent a loop; in \texttt{rewrite} they looped. The rule list
therefore skips a rule whose result equals the term, contains a NaN or a
division by zero, or closes a cycle such as expanding and factoring again
(the result was replaced before, and the chain of the last replacements,
also of subterms, leads back to the term), and a rule that keeps rewriting
the same term. Only the chain counts: a term that was replaced in another
branch, like $\int b\,dx$, may come up again. The matcher also had to learn that an optional
variable already bound to its default value may be missing a second time,
as in $(c+d\tan(e+fx))/(a+b\tan(e+fx))$ with $e=0$, and that products are
flat: Mathematica's pattern $u\,(a+b\arctan x)$ matches
$x^2\arctan x/(1+x^2)$ with $u=x^2/(1+x^2)$, so for a commutative operator
the matcher also tries every split of up to six nested operands into two
groups. Finally, Rubi's
substitutions $\int u\,dx$ with $x\to\sqrt{a+bx}$ rely on Mathematica
treating the new variable as non-negative. \texttt{Subst[Int[u,x],x,v]}
therefore integrates in a fresh constant of sort \texttt{nonneg} when $v$ is
a square root or otherwise non-negative, so that $\sqrt{x^2}=x$ holds
inside; with this, $\int\sin\sqrt{1+x}/\sqrt{1+x}\,dx=-2\cos\sqrt{1+x}$.
Mathematica also writes $(b\tan u)^3$ as $b^3\tan^3u$, so a pattern
$(b\,\tan u)^n$ with integer $n$ always sees $b=1$ there, and some rules
silently drop $b$. The translator adds the condition $b=1$ (or $b=0$ in a
sum) to every rule whose optional variable appears neither in a condition
nor in the result.

Two parts of Rubi lie outside its rule files. Most trigonometric rules exist
only for sine, secant and tangent; Rubi's utility function
\texttt{UnifyInertTrigFunction} first rewrites cosine forms, such as
$a+b\cos(e+fx)$ as $a+b\sin(e+\pi/2+fx)$. Its 69 definitions are translated
by the same program into rules that run before the trigonometric ones, and
the output rules turn $\sin(\pi/2+u)$ back into $\cos u$. Rubi also relies
on Mathematica writing $1/\sin x$ as $\csc x$, and on its own
\texttt{FixInertTrigFunction}, which rewrites products of two trigonometric
functions, e.g.\ $\sec x\sin^2x$ as $\cos^{-1}x\sin^2x$; a C function with
Rubi's tables does both before the rules are tried. Without it, even
$\int dx/\sin x$ remained unsolved. Similarly, functions of
trigonometric functions of different multiples of one angle, such as
$\sin x/\cos 2x$ or $e^{\sin x}\sin 2x$, are written with $\sin x$ and
$\cos x$ first, as Mathematica's \texttt{TrigExpand} does; polynomials in
sines and cosines are left to Rubi's product-to-sum reduction, which the
expansion would undo.
For hyperbolic
functions, Rubi~4.17 has no basic rules; it writes $\sinh v=-i\sin(iv)$,
$\cosh v=\cos(iv)$, \dots{} before its trigonometric rules, and
Mathematica's evaluation turns $\sin(iw)$ back into $i\sinh w$. The same
happens here with the imaginary unit \texttt{im}: a C helper rewrites the hyperbolic functions of
an integrand that is a function of trigonometric or hyperbolic functions of
linear arguments, and the output step takes \texttt{im} out of the
functions again, so that $\int x\sinh x\,dx$ gives $x\cosh x-\sinh x$.
Hyperbolic functions for which still no rule applies are written with
exponentials, $\sinh u=(e^u-e^{-u})/2$, by a last rule.

The complete integration is the algebra list
\begin{lstlisting}
SPEC RubiIntegrate : (RubiNorm,IntRubi,RubiRules),RubiCollect,IntOut,RubiOut
\end{lstlisting}
where \texttt{RubiCollect} combines like summands of the result,
\texttt{IntOut} restores the usual output form and \texttt{RubiOut} writes
the result in a normal form for output in one pass of a C function. The
library's general simplification, which did this before, sorts and
simplifies one rule application at a time; for a polynomial result of 231
terms it needed 24\,000 steps, each followed by a new traversal of the
term, and took most of the time of such integrals. As Rubi, \texttt{rewrite}
can show the solution steps: after \texttt{STEPS RubiRules "file"}, every
rule of the list that is applied is printed with the integral before and
after it, labelled with its Rubi section, number and Mathematica original
from a file that the translator writes along with the rules.

valid for positive bases: $(ab)^c=a^c b^c$, $(a^b)^c=a^{bc}$, which turned

integer exponents or a positive numerical factor, and for terms of the
sorts \texttt{nonneg} and \texttt{positive}. The numerical check of the
harness found these errors, because Rubi's results were differentiated at
negative arguments.

\section{Limits, transforms and differential equations}

With an integrator in place, further parts of calculus are rule files on
top of it. They also show how the pieces of the language combine: functions
defined by rule lists, sign predicates written as rules, and the
interleaving of table look-up and computation.

\paragraph{Limits and definite integrals.} \texttt{limit(u,x,infinity)}
evaluates finite limits at $\pm\infty$ only: polynomials against
exponentials, quotients by their leading terms, and functions such as
$\operatorname{erf}$ with known limits; a limit that is not known or does
not exist stays as it is, so that $\infty-\infty$ never becomes 0. The
sign of a term is decided by the rule functions \texttt{knownpos} and
\texttt{knownneg}, which use the sorts (\texttt{SYM a : positive}) and
the structure of the term. \texttt{Int(f,x,a,b)} takes the antiderivative of
\texttt{RubiIntegrate} at the bounds, with limits at infinity, but only for
integrands that are continuous on the real line, so that
$\int_{-1}^{1}t^{-2}\,dt$ stays unevaluated. Thus
$\int_{-\infty}^{\infty}e^{-at^2}dt$ gives \texttt{pi\^{}(1/2)/a\^{}(1/2)}
and $\int_0^\infty e^{-at}\cos(wt)\,dt$ gives \texttt{a/(w\^{}2+a\^{}2)}.
The Heaviside step and the Dirac delta are handled before the integration.

\paragraph{Laplace transform.} \texttt{laplace(f,t,s)} combines a table
with the theorems (shift, damping, multiplication by $t$, derivatives) and
the definite integral for the rest. The transform of a derivative refers to
the initial values, \texttt{v(0)} and \texttt{initial(Dt(v(t),t),t)}, which
a user supplies as rules. The inverse uses partial fractions; quadratic
denominators give damped oscillations and \texttt{exp(-c*s)} a delay. An
initial value problem is then solved in three steps, here a driven
oscillator at its resonance, $v''+v=\sin t$, $v(0)=v'(0)=0$:

\begin{lstlisting}
SYM s : positive
FUNC v : real >> real     # the unknown function
SYM V : real              # its transform
ALG Init
SPEC    Init : v(0) = 0
ADDSPEC Init : initial(Dt(v(t),t),t) = 0
ADDSPEC Init : laplace(v(t),t,s) = V
E = REWR laplace(Dt(Dt(v(t),t),t) + v(t) - sin(t), t, s) : Init, All
R = REWR solve(E == 0, V) : Solve
Vs = REWR part(R,1) : All               # prints 1 / (1 + s ^ 2 )^ 2
invlaplace(Vs, s, t)      # prints (1/2) * sin (t )- (1/2) * t * cos (t )
\end{lstlisting}

\paragraph{Fourier transform.} \texttt{fourier(f,t,w)} uses the convention
$F(w)=\int f(t)\,e^{-iwt}dt$. Its table holds the entries that are
distributions or need contour integrals (constants and $\cos$ give deltas,
$e^{-a|t|}$, $1/(t^2+c)$, $\sin(at)/t$) and the Gaussians
$e^{-ct^2+bt+d}$, whose transform
$\sqrt{\pi/c}\,e^{d+(b-iw)^2/(4c)}$ is written with the square expanded so
that $i^2=-1$ cancels; the theorems cover modulation, multiplication by
$t$ and derivatives, and the integral of \texttt{inc/limits} the rest. The
inverse is the duality $f(t)=F(w)|_{w\to-t}/(2\pi)$ of the same rules, so
the table works in both directions. The derivative theorem turns a linear
partial differential equation in $x$ into an ordinary one in $t$: for the
heat equation $u_t=a\,u_{xx}$ the transform is $U_t=-aw^2U$, so
$U=U_0(w)\,e^{-aw^2t}$, and a point source gives the heat kernel:

\begin{lstlisting}
SYM w : real
SYM a, t : positive
FUNC v : real,real >> real
REWR fourier(D(D(v(x,t),x),x), x, w) : All
                        # prints - w ^ 2 * fourier (v (x ,t ),x ,w )
invfourier(exp(-a*w^2*t), w, x)
   # prints (1/2) * exp (- (1/4) * x ^ 2 / (a * t ))
   #          / (pi ^ (1/2) * a ^ (1/2) * t ^ (1/2) )
\end{lstlisting}

In the same way an initial Gaussian $e^{-x^2}$ spreads to
$e^{-x^2/(1+4at)}/\sqrt{1+4at}$, and the transport equation
$u_t+cu_x=0$, with $U=U_0\,e^{-icwt}$, moves it to $e^{-(x-ct)^2}$.

\paragraph{Checking and other methods.} Since \texttt{D} differentiates
partially, a proposed solution is checked by substituting it: the wave,
heat and Laplace equations with $\sin(x-ct)$, $e^{-ak^2t}\sin kx$,
$e^{-x^2/(4at)}/\sqrt t$ or $\ln(x^2+y^2)$ reduce to 0 with \texttt{All}
(the last after \texttt{cancel}). The example programs for ordinary
equations also find the characteristic roots with \texttt{solve}, apply
the integrating factor and the separation of variables with
\texttt{RubiIntegrate}, iterate Picard's integral equation with definite
integrals in a loop, and integrate $y'=1+y^2$ with a Runge--Kutta loop
written in the language; they run as part of the test suite.

Some of this needed additions to the library rather than to the
interpreter: the rules $e^ae^b=e^{a+b}$ and $e^{\ln x}=x$ had been missing
from the general simplification, so that integrating factors did not
cancel. And each rule set of these libraries has its own pattern
variables: a rule function called in a condition, such as a sign test,
matches with its own variables and must not rebind those of the rule that
called it. The same concern for the user led to the underscore convention
for the pattern variables of the library (Section~\ref{sec:rules}).
Simplification remains the limiting factor: the second derivatives of a
rational function of $x+ct$ take minutes, and results are not always in
their simplest form.

\section{Implementation and revival}

The interpreter consists of about 20\,800 lines of C (about 8400 in the
original program); the additions of 2026 are the rule lists, subsorts,
exact numbers, special and symbolic helper functions, lists and matrices,
equation solving and the interactive environment. The grammar for the
scanner and parser generators flex and bison has about 590 lines. Terms are binary trees of nodes taken
from memory pools; symbols carry their sort, value and the links used by
\texttt{LIFT}. The rules of an algebra are merged into a single tree, in
which rules with a common left-hand-side structure share nodes and
alternatives branch off where they differ; rule lists are kept in order
instead. Rules are matched against every subterm, innermost first, and a
single \texttt{REWR} stops after $10^5$ steps, so that a looping rule set
cannot hang the interpreter.

The program was written for 32-bit Unix and the Amiga and no longer worked
with current tools. The port to 64-bit Linux and Windows (MSYS2) required
only small changes to the C code itself. The main problems were changed
semantics in the scanner generator, the release of static memory that old
C libraries tolerated, and errors in the handling of declarations inside
loops and included files. A regression test suite with 58 test programs
now covers the core language, the library, the pattern features, exact
numbers, helper and special functions, lists, matrices and equations, the
integration rules, limits and transforms, the original example programs and
the example programs for new users; the integration tests check every result by
differentiating it again. Writing them also uncovered old faults: a
second declaration of a function left its earlier variants in a broken
ring, so that a later lookup did not end, and every message was formatted
into a fixed buffer of 1024 bytes, whose overflow overwrote the file
pointers stored behind it. Memory leaks were removed with an instrumented
build that counts allocations per source line, so that repeated
calculations run in constant memory. All parser structures are now
accessed through named macros instead of chains like
\texttt{np->r->r->l}; for most source files the compiled code stayed
byte-identical, which confirmed that this cleanup did not change the
behaviour. \texttt{rewrite} runs interactively with a prompt, runs program
files given as arguments, or reads a program from a pipe for scripts and
the tests.

Performance is adequate for interactive use. Loading the standard library,
including the translated integration rules, and computing a derivative
takes about 0.5\,s on a current laptop. A scalar loop
written in the language itself needs about 0.2\,$\mu$s per iteration
(measured for $10^7$ iterations of \texttt{s = s + k*k}). We estimate this
to be about two orders of magnitude slower than an equivalent compiled
loop. Operations on whole vectors and matrices run in C.

\paragraph{Library organisation.} \texttt{INC "inc/all"} loads the
mathematical library: the basic sorts and rules, exact numbers, the
symbolic helpers, lists, matrices, equations, both integration rule
sets, limits and the Laplace and Fourier transforms. The physical units and constants of the original application, whose
many short names (\texttt{c}, \texttt{g}, \texttt{m}, \texttt{t}) would
otherwise not be free symbols, are a separate library \texttt{inc/physics}.
The rule list \texttt{All} ends with the normal form of the symbolic
helpers, guarded by a predicate that is true once a term is in it, so that
the step ends; differentiating the result of an integration now gives the
integrand back, where formerly a sum subtracted in brackets stayed
uncollected.

\paragraph{Interactive use.} \texttt{TYPEOF t} prints the sort the sort
system chose for a term, and for a name its kind and value; \texttt{TYPEOF
f} lists the variants of a function. Help texts are part of the library,
declared by \texttt{HELP "name" "text"}; a line beginning with \texttt{?}
shows them, as in Julia, and for a function without a text its variants.
Names may contain Unicode letters, and the LaTeX-like names of Julia's
table (\verb|\alpha| for $\alpha$, about 2500 of them) are replaced on
input. With the line editor wrapper \texttt{rlwrap} and a small filter,
the session behaves like Julia's REPL: \texttt{TAB} completes keywords,
library names and \verb|\alpha|, the arrow keys search the history by the
typed prefix, prompt, keywords, sorts and errors are coloured, and a
startup file is run at the beginning. \texttt{Ctrl-C} stops a running
rewrite or loop instead of ending the program. A folder of short example
programs, run by the tests as well, serves as an introduction.

\section{Discussion}

\paragraph{Strengths.} The main strength of \texttt{rewrite} is that all
mathematics is visible and changeable. Correcting the derivative of
$\arcsin$ meant editing one line of a text file, not the interpreter.
\texttt{LIFT} allows algebraic structure to be expressed once and reused;
with subsorts, it also turned out to be the right mechanism for a numeric
tower, since exact fractions inherited all rules of the real numbers
without any change to them. \texttt{NUMPAT} variables together with conditions
give precise control over when a rule fires. The interleaving of rewriting
and numerical evaluation makes it natural to derive formulas symbolically
and evaluate them numerically in the same program, for example derivatives
for Newton's method.

\paragraph{Limitations.} Commutative matching only swaps the two operands
of one binary operator. Associativity is handled by normalization, so the
integrand must be brought into a fixed form before the rules are tried.
The imaginary unit stays a symbol in terms, but the
general simplification of the library is still written for real numbers,
and logarithms of negative arguments evaluate to NaN although their
derivatives are correct. The sign of a term is only known through the
sorts of its operator variants, so for example $e^x$ is not known to be
positive. Nothing checks that a rule set
terminates or is confluent~\cite{baader1998term}, and the order of rules
matters; the safeguards against loops in rule lists are heuristics.
Numeric conditions such as $m\ne-1$ do not hold for symbolic $m$, which is
more conservative than Rubi. Error messages are minimal.

\paragraph{Related work.} Rule-based simplification is at the core of
Mathematica~\cite{mathematica} and of Rubi~\cite{rich2018rubi}. General
rewriting logic, with order-sorted signatures, is provided by
Maude~\cite{clavel2007maude,goguen1992osa}. More recently, equality
saturation with e-graphs, as in egg~\cite{willsey2021egg} and
Metatheory.jl~\cite{cheli2021metatheory}, avoids the dependence on rule
order by representing many equivalent terms at once. Proof assistants
organize mathematical knowledge in algebraic hierarchies and simplification
rule sets~\cite{mathlib2020}. \texttt{rewrite} anticipated several of these
ideas in a small and self-contained system.

\paragraph{Outlook.} The same approach carries beyond integration. A
library of matrices represents a matrix as a list of rows;
determinants, linear systems and inverses use Bareiss' fraction-free
elimination on sparse polynomials in the atoms of the entries, so that
every division is exact, and the matrix functions thread their arguments
element by element, so that $\det(A-x I)$ is the characteristic
polynomial. Equations are
solved with rules in the style of PRESS~\cite{bundy1981press}: the form of
the equation selects isolation, polynomial methods, a change of the
unknown, the attraction of logarithms or the removal of square roots, and
every solution is checked in the original equation; linear systems use the
fraction-free elimination, nonlinear ones substitution and resultants
(Sylvester determinants). Natural next steps are a
factorization of polynomials over the rationals, partial fractions with
symbolic coefficients, the general simplification for the sort
\texttt{number}, an associative-commutative matcher for sums and products
of any length, and code generation that turns symbolically derived
expressions into compiled numerical code.

\section{Conclusion}

\texttt{rewrite} shows that a small interpreter can host a complete
computer algebra library when the mathematics is expressed as rewrite rules
and rule sets can be combined and lifted between algebraic structures and
number sorts. The automatic translation of 97\% of Rubi demonstrates that
established rule-based algorithms can be imported, and it clarifies which
matching features and which implicit simplifications of the host system
such an import requires.
