\begin{abstract}
Rewrite ist ein System zur Umformung symbolischer Ausdrücke und zum
Durchführen numerischer Rechnungen. Ausdrücke werden in Regelsystemen
(`Algebren') umgeschrieben; so lassen sich Ableitungen, Vereinfachungen,
Integrale und Lösungen von Gleichungen berechnen. Die Sprache selbst kennt
keine Datentypen und keine Operatoren: Sorten, Funktionen und Regeln
werden in Bibliotheken definiert. Die Standardbibliothek \kw{inc/all}
enthält die reellen, komplexen und exakten Zahlen, die elementaren und
viele spezielle Funktionen, Listen und Matrizen, das Lösen von Gleichungen
und eine regelbasierte Integration (eine Übersetzung der Rubi-Regeln).
Numerische Funktionen sind in C geschrieben und werden mit \kw{ATT} an
Funktionen der Sprache gebunden.

Dieses Handbuch beschreibt die Sprache. Die englische Beschreibung
\kw{README.md} enthält dazu die Bibliotheken ausführlicher.
\end{abstract}

\subsection{Übersetzen}
Benötigt werden \kw{gcc}, \kw{flex}, \kw{bison}, \kw{make} und die
GMP-Bibliothek (für die exakten Zahlen).
\begin{description}
\item[Linux:] \kw{make}, danach \kw{make test} für die Tests.
\item[Windows:] MSYS2 installieren (z.\,B.\ mit \kw{winget install
  MSYS2.MSYS2}) und in der MSYS2-Shell einmalig die Werkzeuge:
\begin{beispiel}
pacman -S mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-gmp flex bison make diffutils
\end{beispiel}
  Danach im Projektverzeichnis \kw{build\_windows.bat} aufrufen
  (\kw{build\_windows.bat test} für die Tests). Das erzeugte
  \kw{rewrite.exe} braucht keine weiteren DLLs.
\end{description}

\subsection{Starten}
Starten Sie \rw\ in der Shell im Projektverzeichnis (die Pfade in
\kw{INC} und \kw{DATA} gelten relativ zum aktuellen Verzeichnis) und
geben Sie \kw{INC "inc/all"} ein. Dann können Sie Ihre Aufgabe stellen:
\begin{beispiel}
> INC "inc/all"
> REWR D(sin cos x,x) : All
- cos (cos (x ))* sin (x )
> REWR I(0,1,x^2,x) : numerik,calc
(1/3)
> [[1,2],[3,4]] * [5,6]
[17,
 39]
\end{beispiel}
Das Programm bestimmt die Ableitung von $\sin(\cos x)$ nach $x$ durch
Umschreiben des Terms in der Regelliste \kw{All}.

Eine interaktive Sitzung führt zuerst die Startdatei
\kw{.rewrite/startup.rw} aus, wenn es sie gibt (wie \kw{startup.jl} in
Julia). Sie wird in \kw{HOME} gesucht, dann im Windows-Benutzerverzeichnis.

\section{Eingabe}
\begin{itemize}
\item Die Eingabe wird zeilenweise verarbeitet; jede Zeile wird gleich
  nach dem Lesen ausgeführt.
\item Eine lange Zeile wird mit \verb|\| am Zeilenende fortgesetzt. Hinter
  dem \verb|\| darf kein Zeichen stehen, auch kein Leerzeichen.
\item Ein Block in \verb|{ ... }| darf über mehrere Zeilen gehen.
\item Mehrere Befehle in einer Zeile werden durch \kw{;} getrennt.
\item Kommentare beginnen mit \kw{\#} und gehen bis zum Zeilenende.
\item Eine Zeile, die mit \kw{?} beginnt, zeigt eine Hilfe wie in Julia:
  \kw{?REWR}, \kw{?Int}, \kw{?sin}; \kw{?} allein listet alle Namen mit
  einem Hilfetext. Die Texte stehen in der Bibliothek
  (\kw{HELP "name" "text"}, siehe \kw{inc/help}). Ohne Text zeigt
  \kw{?f} die Varianten einer Funktion und \kw{?x} Art und Wert eines
  Namens.
\item Ein Text in doppelten Anführungszeichen wird ausgegeben. Eine durch
  Kommas getrennte Liste gibt mehreres aus: \verb|"x = ",x|.
\item Ein hingeschriebener Term wird ausgegeben, so weit wie möglich
  ausgerechnet. Der zuletzt ausgegebene Term ist immer als Term \kw{\%}
  verfügbar.
\item Fehler werden mit der fehlerhaften Zeile gemeldet; danach geht es
  mit der nächsten Zeile weiter.
\item Namen dürfen Unicode-Buchstaben enthalten (UTF-8):
  \kw{SYM α, θ₁ : real}. Wie in Julia werden LaTeX-artige Namen bei der
  Eingabe ersetzt: \verb|\alpha| wird zu α, \verb|\_1| zu ₁, \verb|\hbar|
  zu ħ (Julias Tabelle mit etwa 2500 Namen, \kw{src/latex.c}). Ein Name,
  der auf einen Buchstaben endet, darf nicht von einem Buchstaben gefolgt
  sein: \verb|\alphax| bleibt stehen.
\item Unicode-Operatoren sind eigene Zeichen, auch ohne Leerzeichen:
  \kw{a≤b} ist \kw{a ≤ b}, \kw{3×4} ist \kw{3 × 4}. Das sind die Zeichen
  × ÷ · ± ¬, die Pfeile und die mathematischen Operatoren, außer denen,
  die als Namen dienen (∂ ∇ ∞, Summen und Integrale). Ihre Bedeutung
  kommt aus der Bibliothek (\kw{ALIAS}, Abschnitt~\ref{sec:sorten}):
  \kw{inc/alg} liest × als \kw{*}, ebenso ≤ ≥ ≠ ⋅ · ÷ − ∧ ∨ ¬ √ π
  (\kw{√16} ist \kw{sqrt 16}).
\end{itemize}

\section{Datentypen und Operatoren}\label{sec:sorten}
Ohne Bibliothek kennt die Sprache weder Datentypen noch Operatoren. Dieses
vollständige Programm definiert sie selbst:
\begin{beispiel}
SORT real                                   # ein Datentyp
REALNUM real                                # Zahlen wie 1.5 haben den Typ real
FUNC + : real,real >> real LA2 ATT plus     # Operatoren mit Rang und der
FUNC * : real,real >> real LA3 ATT mult     # C-Funktion, die sie ausrechnet
FUNC ^ : real,real >> real RA  ATT power
1+2*3                                       # gibt 7 aus
SYM x,y : real
x+y*2                                       # gibt x + y * 2 aus
x=4
x+y*2                                       # gibt 4 + y * 2 aus
\end{beispiel}

\begin{description}
\item[SORT name {[},name ..{]}]
  Erzeugt einen Datentyp (eine `Sorte'). Sorten werden bei Funktionen,
  Symbolen und Termen gebraucht.

\item[REALNUM sortname]
  Alle eingegebenen Zahlen (z.\,B.\ \kw{1.234}) bekommen diese Sorte; sie
  werden als \kw{double} gespeichert. Vor \kw{REALNUM} ist eine Zahl ein
  Fehler. Bsp.: \kw{SORT real} \quad \kw{REALNUM real}

\item[INTNUM sortname ATT name]
  Zahlen ohne Punkt und Exponent bekommen diese Sorte; die C-Funktion
  \kw{name} erzeugt den Wert aus dem Text. So macht \kw{inc/exact} sie zu
  exakten ganzen Zahlen (GMP).

\item[SUBSORT a,b {[}ATT name{]}]
  Jeder Wert der Sorte \kw{a} ist auch einer der Sorte \kw{b}
  (\kw{integer} $<$ \kw{rational} $<$ \kw{real}); die C-Funktion wandelt
  einen Wert um. Eine Funktion für \kw{real} nimmt dann auch exakte
  Argumente. Passen mehrere Varianten einer Funktion, so hat eine genau
  passende Vorrang, sonst gewinnt die mit den wenigsten Umwandlungen.
  Ohne \kw{ATT} hat \kw{b} keine eigenen Werte: so sind \kw{number}
  (oberhalb von \kw{real} und \kw{complex}), \kw{algebra}, \kw{vector}
  und \kw{matrix} Sorten für symbolische Ausdrücke. Regeln für \kw{number}
  gelten für alle Terme darunter.

\item[SYM name {[},name ..{]} : sortname]
  Deklariert ein Symbol (bis 2026 \kw{CONST}). Es steht für sich selbst
  und wird mit seinem Namen ausgegeben, oder es hat einen Wert seiner
  Sorte (\kw{x = 4}); es ist also eine Variable im üblichen Sinn. Ein
  Symbol einer Sorte ohne Werte (\kw{number}) hat keinen Wert.

\item[TERM name {[},name ..{]} : sortname]
  Deklariert eine Term-Variable, die einen ganzen Ausdruck speichert
  (Abschnitt~\ref{sec:zuweisung}).

\item[PAT name {[},name ..{]} : sortname]
  Deklariert eine Muster-Variable (bis 2026 \kw{VAR}). Sie steht in Regeln
  für einen beliebigen Term ihrer Sorte oder einer Sorte darunter.
  Bsp.: \kw{PAT A : real} \quad \kw{SPEC xyz : A+0=A}\\
  Die Muster-Variablen der Bibliothek beginnen alle mit \kw{\_}
  (\kw{\_X}, \kw{\_Xnu}, \kw{\_N}), damit Namen wie \kw{X} oder \kw{A}
  frei bleiben und ein \kw{TERM Y} des Benutzers keine Regel der
  Bibliothek verändert. Eigene Regeln deklarieren ihre eigenen
  Muster-Variablen.

\item[NUMPAT name {[},name ..{]} : sortname]
  Deklariert eine Muster-Variable, die nur für Zahlen steht (bis 2026
  \kw{NUM}). Bsp.: \kw{NUMPAT N : real} \quad \kw{SPEC xyz : N+0=N}

\item[TYPEOF term, TYPEOF f]
  Gibt die Sorte eines Terms aus; für einen Namen auch seine Art
  (\kw{SYM}, \kw{TERM}, \kw{PAT}, \kw{NUMPAT}) und seinen Wert oder Term,
  für eine Funktion alle Varianten mit ihren Sorten.

\item[FUNC name : sortliste >{}> sortname {[}LA1..LA5|RA|RU{]} {[}ATT ..{]}]
  Erzeugt eine Funktion. Die Sortenliste gibt Anzahl und Sorten der
  Argumente an; ein \kw{++} hinter der letzten Sorte steht für beliebig
  viele Argumente dieser Sorte. Der zweite Sortenname ist die Sorte des
  Ergebnisses. Das Ein- und Ausgabeformat:
  \begin{description}
  \item[LA1 bis LA5] links-assoziativer Operator mit zwei Argumenten;
    \kw{LA5} bindet stärker als \kw{LA4} usw.
  \item[RA] rechts-assoziativer Operator, z.\,B.\ \verb|a^b|.
  \item[RU] rechts-unärer Operator, z.\,B.\ die Fakultät \kw{3!}.
  \item[ohne] die Funktion wird als \kw{sin x}, \kw{sin(x)} oder
    \kw{f(x,y)} geschrieben.
  \end{description}
  Was die Funktion ausrechnet, legt \kw{ATT} fest:
  \begin{description}
  \item[ATT name] die C-Funktion \kw{name} aus der Liste
    \kw{userfunction} in \kw{src/userfn.c}. Sie wird aufgerufen, wenn alle
    Argumente einen Zahlenwert haben; sonst bleibt die Funktion symbolisch.
    Bsp.: \kw{FUNC sqrt : real >{}> real ATT r\_sqrt}
  \item[ATT SYMBOLIC name] eine symbolische C-Funktion aus
    \kw{src/symfn.c}; sie bekommt die Argumente als Terme und gibt einen
    neuen Term zurück (z.\,B.\ \kw{expand}, \kw{coeff}, \kw{normform}).
    Mit \kw{ATT SYMBOLIC HOLD name} bekommt sie die Argumente
    unausgewertet.
  \item[ATT RULES algliste] die Funktion wird durch Umschreiben berechnet:
    \kw{f(a,b)} wird zu \kw{REWR f(a,b) : algliste}. Ist das Ergebnis
    wieder ein Aufruf von \kw{f}, so bleibt der Aufruf stehen. So ist die
    Ableitung \kw{deriv} in \kw{inc/helpers} definiert.
  \item[ATT ( Argdefs ) Block] eine in der Sprache selbst geschriebene
    Funktion. \kw{( Argdefs )} sind Definitionen der Argumente (Symbole,
    Terme oder Funktionen). Der Block wird ausgeführt, wenn der Term
    berechnet wird:
\begin{beispiel}
FUNC fma3 : real,real,real >> real ATT (SYM aa,bb : real; TERM cc : real) \
            { RETURN cc+aa*bb }
fma3(2,3,4)          # gibt 10 aus
\end{beispiel}
  \end{description}

\item[RETURN term]
  Setzt das Ergebnis einer selbst geschriebenen Funktion. Die Ausführung
  der Funktion wird dadurch \emph{nicht} beendet.

\item[OTHER name : sortliste >{}> sortname {[}ATT name{]}]
  Gibt einem vorhandenen Funktionsnamen eine weitere Bedeutung für andere
  Argument- und Ergebnissorten. Funktionen werden anhand der Sorten ihrer
  Argumente unterschieden. Bsp.: \kw{OTHER + : vector,vector >{}> vector}

\item[BRA auf zu : sortliste >{}> sortname {[}ATT name{]}]
  Definiert eine Funktion in Klammerschreibweise; \kw{auf} und \kw{zu}
  sind die Klammersymbole. Statt \kw{[a,b,c]} darf man \kw{a[b,c]}
  schreiben, so lassen sich Vektoren mit \kw{v[1]} indizieren. Bei
  \kw{OTHER} kennzeichnet die erste Klammer die Funktion.
  Bsp.: \kw{BRA < > : vector,vector >{}> real} \quad \# Skalarprodukt \kw{<a,b>}

\item[ATT sortname Name1,Name2,Name3,Name4]
  Gibt einer Sorte die C-Funktionen zum Anzeigen, Vergleichen, Kopieren
  und Löschen ihrer Werte (aus \kw{userfunction}). Die
  Vergleichsfunktion liefert 1, 0 oder $-1$ für $>$, $=$, $<$.
  Bsp.:
\begin{beispiel}
ATT complex show_complex,cmp_complex,cpy_complex,del_complex
\end{beispiel}

\item[SHOW f {[}ATT name{]}]
  Terme mit der Funktion \kw{f} werden mit der C-Funktion \kw{name}
  ausgegeben; \kw{SHOW f} allein schaltet zurück. So gibt \kw{inc/list}
  einen Vektor als Spalte und eine Matrix als Gitter aus.

\item[ALIAS "name" = "symbol"]
  Der Name wird von nun an als das Symbol gelesen; die Ausgabe zeigt das
  Symbol. Bsp.: \kw{ALIAS "×" = "*"}, dann ist \kw{3×4} gleich 12.

\item[SYMBOLIC "rolle" = "symbol"]
  Die symbolischen C-Funktionen kennen die Operatoren der Bibliothek über
  Rollen (\kw{"+"}, \kw{"cos"}, \kw{"pi"}, \ldots). Eine Bibliothek mit
  anderen Namen ordnet sie so zu: \kw{SYMBOLIC "cos" = "kos"}.
  \kw{SYMBOLIC} allein löscht die Zuordnung.

\item[HELP "name" "text"]
  Fügt der Hilfe zu \kw{name} eine Zeile hinzu, die \kw{?name} anzeigt.
\end{description}

\section{Regelsysteme und Umschreiben}
\begin{description}
\item[ALG name {[},name ..{]}]
  Definiert ein neues Regelsystem (eine `Algebra').

\item[SPEC alg : {[}IF bedingung{]} links = rechts {[}DO block{]}]
  Löscht die alten Regeln von \kw{alg} und trägt diese Regel ein.

\item[ADDSPEC alg : {[}IF bedingung{]} links = rechts {[}DO block{]}]
  Fügt \kw{alg} eine Regel hinzu. Muster-Variablen dürfen auf beiden
  Seiten stehen. Ist \kw{DO} mit einem Block angegeben, so wird der Block
  vor dem Ersetzen ausgeführt.

\item[SPEC alg : alg1, alg2, ..]
  \kw{alg} steht für die Liste der Regelsysteme, die nacheinander
  angewandt werden. Eine Liste in Klammern, z.\,B.\
  \kw{(Linear,Compl,diff)}, wird so lange angewandt, bis sich nichts mehr
  ändert. Die Regelsysteme werden durch Kommas getrennt (in älteren
  Versionen durch \kw{;}).

\item[REWR term : alg {[},alg ..{]}]
  Schreibt den Term mit den Regelsystemen nacheinander um und gibt das
  Ergebnis aus. Mit \kw{t = REWR term : alg} wird es in der Term-Variablen
  \kw{t} gespeichert.

\item[LIFT (funktionen) TO (funktionen)]
  Überträgt alle Regeln, die für eine Menge von Funktionen und Konstanten
  gelten, auf eine andere. Die Funktionen werden durch die Sorten ihrer
  Argumente gekennzeichnet; die Argumente selbst spielen sonst keine Rolle.
  Als Konstanten sind auch 0 und 1 möglich. Mit diesem Trick folgen die
  Ringregeln aus den Gruppenregeln:
\begin{beispiel}
LIFT (_Aag+_Aag,_Aag-_Aag,-_Aag,0ag) TO (_Ar+_Ar,_Ar-_Ar,-_Ar,0r)
LIFT (_Aag+_Aag,_Aag-_Aag,-_Aag,0ag) TO (_Ar*_Ar,_Ar/_Ar,mi(_Ar),1r)
\end{beispiel}
\end{description}

\subsection{Bedingungen}
Eine Regel gilt nur, wenn ihre Bedingungen erfüllt sind:
\begin{description}
\item[LB(term,term)] `lower or between': eine Ordnung der Terme, z.\,B.\
  zum Sortieren von Summen: \kw{ADDSPEC real : IF LB(A,B) B+A=A+B}.
\item[IN(a,b)] der Term \kw{a} kommt in \kw{b} vor. \kw{NIN(a,b)} ist
  die Verneinung; \kw{NIN(x,a,b,c)} prüft, dass \kw{x} in keinem von
  \kw{a}, \kw{b}, \kw{c} vorkommt.
\item[(term)] ein Ausdruck mit einem Wahrheitswert, z.\,B.\
  \kw{(is\_int(N))} oder \kw{(N > 0)}. Lässt er sich nicht ausrechnen
  (etwa weil \kw{N} symbolisch ist), so gilt die Bedingung nicht.
\end{description}
Mehrere Bedingungen werden durch Kommas getrennt und müssen alle gelten:
\kw{IF NIN(x,A), (N > 0) \ldots}

\begin{beispiel}
PAT A : real
ALG einfach
SPEC einfach : A*1=A
ADDSPEC einfach : A+0=A
SYM u : real
REWR (u*1)+0 : einfach      # gibt u aus
\end{beispiel}

\subsection{Optionale Teile und kommutative Operatoren}
Drei Befehle lassen eine Regel viele Formen eines Terms erfassen. Sie
gelten für die danach definierten Regeln:
\begin{description}
\item[OPT A,B] die Muster-Variablen \kw{A}, \kw{B} dürfen im Term fehlen.
\item[DEFAULT + = 0] ein fehlender Operand von \kw{+} hat den Wert 0;
  \kw{DEFAULT RIGHT \^{} = 1}: nur der rechte Operand von \kw{\^{}} darf
  fehlen.
\item[COMM +,*] Muster mit \kw{+} und \kw{*} passen auch mit vertauschten
  Operanden.
\item[OPT, DEFAULT, COMM] ohne Argumente: löscht die Liste wieder.
\end{description}
Solche Regeln stehen nicht im Regelbaum, sondern in einer geordneten
Regelliste (wie in Mathematica oder Rubi): die erste passende Regel
gewinnt. Der Matcher (\kw{src/listmatch.c}) probiert vertauschte
Operanden, andere Klammerungen und fehlende Operanden mit Backtracking
durch; schlägt eine Bedingung fehl, so wird die nächste Möglichkeit
versucht. Ein Ergebnis, das dem Term gleicht, einen NaN enthält oder einen
Zyklus schließt, wird übersprungen.

\subsection{Grenzen und Lösungsschritte}
\begin{description}
\item[MAXSTEPS {[}n{]}]
  Ein \kw{REWR} bricht nach \kw{n} Umschreibschritten ab (voreingestellt
  100000) mit der Meldung \kw{REWR : step limit ... reached}. Regeln, die
  sich im Kreis drehen, halten \rw\ so nicht auf. Ohne \kw{n} wird die
  Grenze angezeigt.
\item[MAXDEPTH {[}n{]}]
  Eine Regel, die den Term bei jedem Schritt tiefer macht, etwa
  \kw{lin(c) = c*lin(1)} (sie passt wieder auf \kw{lin(1)}), würde den
  Stapel des Interpreters lange vor der Schrittgrenze überlaufen lassen.
  \kw{REWR} bricht deshalb auch ab, wenn der Term tiefer als \kw{n} Ebenen
  wird (voreingestellt 1000; eine Summe von 1000 Summanden ist 1000 Ebenen
  tief). Eine höhere Grenze kostet bei einer solchen Regel Zeit, eine sehr
  hohe kann \rw\ zum Absturz bringen.
\item[STEPS alg "datei"]
  Zeigt jede angewandte Regel der Regelliste von \kw{alg} (die
  Lösungsschritte), beschriftet aus \kw{datei} (Zeilen
  \kw{nummer<TAB>name<TAB>text}); \kw{STEPS alg ""} schaltet es ab.
\end{description}

\section{Term-Variablen und Zuweisungen}\label{sec:zuweisung}
\begin{description}
\item[termname = term]
  Speichert den Term in der Term-Variablen. Wird eine Term-Variable einer
  anderen zugewiesen, so wird der Inhalt kopiert (und, wo möglich,
  ausgerechnet); spätere Änderungen wirken sich nicht aus. Lokale Symbole
  eines Blocks dürfen nicht in globale Terme gelangen.
\item[symbol = wert]
  Gibt einem Symbol einen Wert, z.\,B.\ \kw{x = 1+1+3}. Lässt sich der
  Wert nicht ausrechnen, so verliert das Symbol seinen Wert und wird
  wieder mit seinem Namen ausgegeben. Das Symbol \kw{nothing} der
  Bibliothek hat nie einen Wert, so löscht \kw{a = nothing} den Wert von
  \kw{a}.
\end{description}
Symbole und Term-Variablen werden durch Hinschreiben ihres Namens
ausgegeben. Eine Term-Variable wirkt wie eine Funktion ihrer Symbole:
\begin{beispiel}
TERM tt,qq : real
tt = a+b
tt*2                # gibt (a + b )* 2 aus
%+1                 # gibt (a + b )* 2 + 1 aus
qq = x^y*a          # wie eine Funktion qq(x,y,a)
x=4
y=2
a=3
qq                  # gibt 48 aus
a = nothing
a + 1               # gibt a + 1 aus
\end{beispiel}

\section{Kontrollstrukturen}
\begin{description}
\item[FOR symbol = n1 TO n2 {[}STEP n3{]} DO block]
  Schleife über ein Symbol. Bsp.: \kw{FOR n = 20 TO 10 STEP -1 DO n}
\item[IF (bedingung) block {[}ELSE block{]}]
  Bedingung mit einem Wahrheitswert. Bsp.:
  \kw{IF (n > 3) "gross" ELSE "klein"}
\item[WHILE (bedingung) block]
  Schleife. Bsp.: \kw{WHILE (n < 100) n = n*2}
\item[\{ \ldots\ \}]
  Block. Die in einem Block deklarierten Symbole sind lokal und werden
  bei jedem Schleifendurchlauf neu angelegt:
\begin{beispiel}
FOR n = 1 TO 3 DO { SYM s : real
                    s = n*10
                    PRT s }
\end{beispiel}
\end{description}

\section{Ein- und Ausgabe}
\begin{description}
\item[INC "datei"]
  Liest die Datei und führt sie aus. \kw{INC} darf geschachtelt werden.
  Eine Zeile mit \kw{INC} darf nicht mit \verb|\| fortgesetzt werden.
  Steht \kw{INC} in einem Block, so sind die Definitionen der Datei
  trotzdem global.
\item[PRT liste]
  Gibt aus, ohne Zeilenende.
\item[PRTNUM "format"]
  Das C-Format für reelle Zahlen, z.\,B.\ \kw{PRTNUM "\%.10g "}.
\item[OUT "datei"]
  Lenkt die Ausgabe in die Datei um, die vorher gelöscht wird;
  \kw{OUT "stdout"} schaltet zurück. So lassen sich Daten für
  Grafikprogramme erzeugen.
\item[DATA "datei"]
  Öffnet eine Datei zum Lesen von Zahlen.
\item[DATA symbol]
  Liest die nächste Zahl aus der geöffneten Datei in das Symbol;
  nichtnumerischer Text bis zum Zeilenende wird übersprungen. So lassen
  sich z.\,B.\ Messwerte weiterverarbeiten.
\item[SYS "befehl"]
  Führt einen Befehl der Shell aus.
\item[DEBUG n]
  Setzt die Debug-Stufe des Interpreters.
\item[INFO name]
  Art und Sorten eines Namens (ältere Form von \kw{TYPEOF}).
\item[QUIT]
  Beendet \rw.
\end{description}

\section{Eigene C-Funktionen}
Neue numerische Funktionen werden in C geschrieben und in die Liste
\kw{userfunction} in \kw{src/userfn.c} eingetragen. Eine Funktion bekommt
ein Feld von Zeigern auf ihre Argumente und gibt einen Zeiger auf ein neu
angelegtes Ergebnis zurück:
\begin{beispiel}
double * r_abs (double * arg[]) { return mkreal(fabs(* arg[0])); }
\end{beispiel}
Beispiele stehen in \kw{real.c}, \kw{complex.c}, \kw{vector.c} und
\kw{matrix.c}. Mit \kw{ATT} in einer \kw{FUNC}- oder
\kw{OTHER}-Deklaration wird die Funktion angebunden.

Symbolische Funktionen, die auf Termen statt auf Zahlen arbeiten, stehen
in der Liste \kw{symfunction} in \kw{src/symfn.c}. Sie bekommen die
Argumente als Terme und geben einen neuen Term zurück, oder \kw{NULL},
wenn sie nicht passen; angebunden werden sie mit \kw{ATT SYMBOLIC name}.
Den Code halten sie frei von Namen der Bibliothek: sie erkennen und bauen
Terme über Rollen (\kw{is\_head(t, "+", 2)}, \kw{fsym("cos")}), die
\kw{SYMBOLIC} zuordnet.

\section{Bekannte Einschränkungen}
\begin{itemize}
\item Bei Syntaxfehlern und beim Überdefinieren von Definitionen geht noch
  etwas Speicher verloren. Wiederholte Rechnungen, Umschreibungen und
  Schleifen laufen ohne Speicherverlust.
\item Nicht jede Regel, die man erwarten könnte, ist vorhanden; so werden
  \kw{ln(exp x)} und $\sin^2 x+\cos^2 x$ nicht vereinfacht.
\item Symbole ohne Wert dürfen von jeder Variablen abhängen, deshalb
  bleibt \kw{D(a,x)} im Ergebnis stehen (gewollt: Differentialgleichungen
  benutzen \kw{D(y,x)}). \kw{deriv} behandelt dagegen jeden Term ohne
  \kw{x} als Konstante.
\item Das kommutative Matching vertauscht nur die zwei Operanden eines
  Operators; Summen und Produkte sind binäre Bäume, deren Summanden nicht
  über Ebenen hinweg umgeordnet werden. \kw{COMM *} gilt auch für Regeln
  mit Matrixprodukten; \kw{COMM} allein schaltet es nach den Regeln, die
  es brauchen, wieder ab.
\end{itemize}
